# 标注规范（初稿）

> 历史文档：以下为早期 JSONL 方案，不用于当前流程，其中 happy、text、sha256 等示例不适用于当前意图标注 CSV。请按 [数据集构建操作指南](dataset_workflow.md) 第 8～9 节操作，当前使用 `intent-draft-v1` 和 `build_annotation_page.py`。

当前采用单标签结构，`configs/labels.yaml` 仅是示例，正式采集前需明确是否改为多标签，以及情绪、意图、梗类型是否分别标注。

每行一个 JSON 对象：

```json
{"image_path":"example.png","sha256":"替换为扫描生成的64位散列","duplicate_of":"","text":"图片上的文字","label":"happy"}
```

- `image_path` 相对 `data/raw/images/`，保留扫描生成的路径与散列，不手动编造。
- `text` 为人工转录或经人工校对的 OCR 文字；无文字时留空。尚未转录与确认无文字目前无法通过字段区分，标注者应在提交前完成检查。
- `label` 必须属于配置中的标签，空标签不能参与划分。
- `duplicate_of` 记录完全重复文件的代表路径。完全重复图片须保持标签一致。
- 不根据图片标签推断发送者的真实心理状态；不确定的样本先留在待标注集合，由人工复核。
- 相似模板、裁剪图、加字版本不一定具有相同文件散列。正式实验需要进一步做近似去重和来源分组。
- 原图保持不变，中间结果写入 `data/interim/`，人工结果写入 `data/annotations/`。
- 当前划分依据重复组数量，比例向下取整后余数归 test；不保证每类在三个集合均有样本。
- 配置更改后须重新校验；测试集确定后保持独立，不能用它调参。
